# Reading state from S3

`tfviz state` can read an exact state object from S3 using your existing AWS credentials.

```bash
aws sso login --profile work
tfviz state \
  --input s3://example-state-bucket/prod/platform/terraform.tfstate \
  --aws-profile work \
  --aws-region eu-west-1 \
  --output state-report.html
```

tfviz makes a single `GetObject` request for the object you name. It never lists buckets, writes objects, takes Terraform state locks or calls secret-value APIs. The object is read through the same state reader as a local file, and only the sanitised report leaves the process.

## Options

| Option | Meaning |
| --- | --- |
| `--aws-profile` | The profile to use. Without it, the standard AWS SDK chain applies: environment variables, shared configuration and SSO sessions, web identity, then container and instance roles. |
| `--aws-region` | The state bucket's region. This can differ from the region your infrastructure runs in. |
| `--s3-version` | Read a specific object version. |
| `--expected-bucket-owner` | Fail unless the bucket belongs to this account ID. |

`--offline` refuses `s3://` inputs. Use it in pipelines that must stay offline.

## Credentials

Credentials stay inside the AWS SDK. tfviz never reads, prints or stores them, and they never reach the report.

- **An expired or missing SSO session** gives you the exact `aws sso login --profile …` command to run. tfviz never starts a login itself, so CI jobs fail with a clear message instead of waiting for a browser.
- **In CI**, use a workload role (web identity, or an ECS or EC2 role) or environment credentials.

## Least-privilege permissions

These requirements come from the Amazon S3 GetObject API reference and the SSE-KMS user guide.

| Reading | Needs |
| --- | --- |
| The current object | `s3:GetObject` on the object |
| A specific version (`--s3-version`) | `s3:GetObjectVersion` on the object (`s3:GetObject` is not needed) |
| An SSE-KMS encrypted object | `kms:Decrypt` on its key, in the key policy or an IAM policy |

You do not need `s3:ListBucket`. Without it, S3 reports a missing object as access denied rather than not found, and tfviz's message says so.

An example identity policy for a pipeline role, scoped to one state object and its key:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadOneStateObject",
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:GetObjectVersion"],
      "Resource": "arn:aws:s3:::example-state-bucket/prod/platform/terraform.tfstate"
    },
    {
      "Sid": "DecryptThatObject",
      "Effect": "Allow",
      "Action": "kms:Decrypt",
      "Resource": "arn:aws:kms:eu-west-1:111122223333:key/<key-id>",
      "Condition": {
        "StringEquals": {
          "kms:EncryptionContext:aws:s3:arn": "arn:aws:s3:::example-state-bucket/prod/platform/terraform.tfstate"
        }
      }
    }
  ]
}
```

S3 uses the object ARN as the KMS encryption context. If the bucket uses S3 Bucket Keys, the context is the **bucket** ARN instead, so set the condition value to `arn:aws:s3:::example-state-bucket`.

## What the report records

The report records the object's last-modified time and, for versioned buckets, its version ID. That time describes the state object. It does not prove the infrastructure in AWS still matches it.

## Encrypted OpenTofu state

OpenTofu can encrypt state and plans. tfviz recognises an encrypted object and stops; it never tries to decrypt it. Export it with your encryption configuration instead:

```bash
tofu show -json | tfviz state --input - --output state-report.html
```

## Testing

The S3 path is tested against a local S3-compatible server in an isolated AWS environment. The tests check the request (a single GET, plus version and expected-owner headers), metadata recording, and every error explanation, including an expired SSO session and missing credentials. Before a release, also check it against a dedicated test bucket using an SSO profile and a CI workload role.
