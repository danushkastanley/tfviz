Security and privacy

Secrets stay out, by design

Plans and state can contain secrets. tfviz is built so that only an approved, sanitised model of your infrastructure ever reaches the report.

How data moves through tfviz

Raw values never leave the reader. Everything after it works on a sanitised model.

  1. Plan or stateMay contain secrets
  2. ReaderTurns sensitive values into markers with no payload
  3. ProjectionKeeps only approved fields for each resource type
  4. ReportSanitised model in one offline HTML file

What tfviz never does

Never sends your data

No telemetry, no accounts and no hosted service. Reports make no network requests and run under a strict content security policy.

Never shows secret values

Passwords, user data, environment variables, tags, policies and secret contents are withheld. A sensitive change is shown only as changed or unchanged.

Never touches your state

S3 access is a single read-only request for the object you name. No listing, no writes, no state locks and no secret-value APIs.

Limits

  • Normal reports are sensitive. They show approved names, IDs, ARNs and network details by design, so protect them like other infrastructure artefacts.
  • Safe-share is not anonymity. The shape of your architecture may itself be confidential.
  • Names can carry secrets. No heuristic can prove that an arbitrary name is harmless.
  • Snapshots are not live. State and plans describe a recorded moment. Relationships are recorded associations, not observed traffic.
  • tfviz can't clean your producer files. The exported JSON and Terraform's own plan files can contain plaintext secrets. Pipe the JSON instead of saving it.

Report a vulnerability

Please report security issues privately, as described in SECURITY.md. Never attach a real plan, state file or unredacted report to a public issue.
